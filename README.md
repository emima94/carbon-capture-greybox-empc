# carbon-capture-greybox-empc

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23377240.svg)](https://doi.org/10.5281/zenodo.23377240)

This repository contains the code that reproduces the results and figures of the paper:

> E. S. Martinsen, S. Frandsen, T. Scharling, J. K. Møller, H. Madsen, T. K. S. Ritschel, G. Goranović, *Neural network-based Grey-box Modeling and Economic Model Predictive Control of a Solvent-based Carbon Capture Pilot Plant*, submitted to Journal of Process Control. Preprint: [10.2139/ssrn.7329166](https://doi.org/10.2139/ssrn.7329166).

It contains the model, state-estimation and control code, and one driver script per step. The pipeline goes from the raw plant logs to the data series, the parameter estimation, the model validation, and the EMPC demonstration. All figures and results are generated by the code.

## Data

The data are published separately on Zenodo: [10.5281/zenodo.23377661](https://doi.org/10.5281/zenodo.23377661). This covers the raw pilot-plant logs, the parameter estimates, and the data from the EMPC tests at the pilot plant. Download the three zip files and extract them in `data/`, so that it contains:

```
data/
├── raw_pilot_plant/
├── parameter_estimates/
└── closed_loop_tests/
```

[`data/README.md`](data/README.md) describes the data files. The data series in `data/pilot_plant_series/` are computed from the raw logs by driver 01.

## Quick start

Requirements:
- The data in `data/` (see above)
- Julia 1.12 (tested with 1.12.4)
- A LaTeX installation with `lualatex` and `pgfplots`, used by PGFPlotsX for Figure 13

From this folder, install the packages (the exact versions are pinned in `Manifest.toml`):

```bash
julia --project=. -e "using Pkg; Pkg.instantiate()"
```

Then run all drivers except the parameter estimation (about 10 minutes):

```bash
julia --project=. run_all.jl
```

Or run a single driver, e.g.:

```bash
julia --project=. --threads=auto drivers/06_fig_rmse.jl
```

Figures are written to `figures/` and tables and numerical results to `results/`. Drivers 03–10 use the data series from driver 01. Drivers 05 and 06 also use `results/predictions.jld2`, which driver 04 computes.

The parameter estimation (driver 02) runs in its own environment with the package versions used on the HPC cluster:

```bash
julia --project=estimation_env -e "using Pkg; Pkg.instantiate()"
```

```bash
julia --project=estimation_env --threads=auto drivers/02_estimate_parameters.jl -1.0 1
```

The arguments are $\log_{10}(\lambda_{reg})$ and the run: 1 is the in-sample estimate, 2–11 leave out series 1–10, or `all`. One run takes 10–50 minutes, so all 121 estimates take about 50 CPU hours. That's why the other drivers use the published estimates in [`data/parameter_estimates/`](data/parameter_estimates/).

## Contents

```
carbon-capture-greybox-empc/
├── run_all.jl          Runs all drivers except the parameter estimation
├── drivers/            One script per step (see table below)
├── src/                Data processing, model, EKF, OCP and plotting functions
├── data/               Data, downloaded from Zenodo (see data/README.md)
├── estimation_env/     Julia environment for the parameter estimation (package versions of the HPC runs)
├── tools/              Script that exported the data from the original project folders (not needed to reproduce)
├── figures/            Generated figures
└── results/            Generated tables and numerical results
```

Most files in `src/` are verbatim copies of the original source files of the project. The exceptions:
- [`src/setup_core.jl`](src/setup_core.jl), [`src/setup.jl`](src/setup.jl): load packages and source files, define paths and small helpers to load the data and parameter estimates and to build the model.
- [`src/raw_data_processing.jl`](src/raw_data_processing.jl): processing of the raw pilot-plant logs. It follows the original data analysis of the pilot plant (folder `DTI_pilot_data_analysis`), restricted to the campaign used in the paper.
- [`src/closed_loop_data.jl`](src/closed_loop_data.jl): verbatim copies of the functions from `util_closed_loop_MPC.jl` for loading the EMPC test data and for the state estimation in each control interval. It also includes the version of the data loading that the controller used during the tests.
- [`src/empc_settings.jl`](src/empc_settings.jl): the settings of the closed-loop EMPC tests, as in `src/settings/settings_closed_loop_test_2604{15,16}_01.jl` of the original project, with the published parameter estimate.

## The closed-loop EMPC replay

During tests #3 and #4, the EMPC ran in real time at the pilot plant. Every 10 minutes it loaded the newest plant data, updated the state estimate with the EKF, solved the OCP with IPOPT, and sent the first optimal inputs to the plant. Driver 09 runs the same controller offline on the logged plant data. In each control interval it uses the data up to the start of the interval. It then compares the computed inputs with the inputs the controller computed during the tests.

The replay can't be exact: the data available to the controller at each moment depended on the latency of the online data download. The OCP is sensitive to small changes in the data, e.g. in the 30 min mean of the disturbances. The replayed inputs agree closely with the logged ones. The mean differences are about 0.001 m³/h for $F$ and 0.01 °C for $T_d^{sp}$, and the maximum differences are below 0.01 m³/h and 0.04 °C. The median relative difference of the OCP objective is 0.2%, and all 72 OCPs are solved to local optimality.

The evaluation of all four tests (Figures 13 and 14) uses the measured plant data and the inputs that were applied during the tests.

## Verification

The reproduced results were compared with the results behind the submitted manuscript:
- **Raw data:** the data series computed from the raw logs by driver 01 are identical to the original data series (all values in all 10 series).
- **Parameter estimation:** the in-sample estimate for $\lambda_{reg} = 0.1$ was re-estimated with driver 02 on a laptop (Apple M2).
  - It starts from the same random initial parameters as the HPC run: the initial loss is 2.6727452273 vs 2.6727452248 on the HPC cluster. The package versions are the same, so the difference in the 9th digit most likely comes from floating-point arithmetic on different processors.
  - The optimization ends at a loss of 1.2193, vs 1.2186 for the published estimate. The NN weights differ, since they aren't uniquely identifiable.
  - The predictive performance is the same: the in-sample 1 h ahead RMSE is 0.408 vs 0.404 vol% for $y_g$, and 1.553 vs 1.552 kW for $Q$.
- **Predictions:** the predictions and RMSEs of driver 04 are identical (zero difference) to the original results for all 220 combinations of parameter estimate and data series.
- **Figures:**
  - Figures 4–7 are byte-identical to the manuscript figures, apart from the PDF creation date.
  - Figure 13 is pixel-identical, and the Figure 14 TikZ files are identical.
  - Figures 8, 9 and 12 have the same data. Their rendering differs slightly (sub-point shifts of the layout and legend line widths), since GR renders the LaTeX labels with the local TeX installation.
- **EMPC:** see the replay section above.
